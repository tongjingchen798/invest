# 操作冻结金额功能说明

## 功能概述
`freeBalance` 接口用于后台管理员操作用户冻结金额，支持冻结和解冻操作，并记录详细的交易明细。

## 接口信息
- **接口路径**: `PUT /user/freeBalance`
- **接口名称**: 操作冻结金额
- **操作日志**: 操作冻结金额

## 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 用户ID |
| balance | Long | 是 | 金额（分） |
| balance_type | Integer | 是 | 操作类型：1-冻结金额，2-解冻金额 |
| remark | String | 否 | 备注信息 |

## 请求示例
```bash
PUT /user/freeBalance?id=1958922146164248577&balance=5000&balance_type=1&remark=测试冻结金额
```

## 功能特性
1. **参数验证**: 验证用户ID、金额和操作类型的有效性
2. **余额检查**: 冻结时检查可用余额，解冻时检查冻结余额
3. **事务管理**: 使用事务确保数据一致性
4. **详细日志**: 记录操作过程和结果
5. **余额明细**: 自动记录余额变动明细

## 业务逻辑
1. 验证输入参数（用户ID、金额、操作类型、备注）
2. 查询目标用户信息
3. 根据操作类型处理冻结金额：
   - 冻结金额：从可用余额扣除，增加到冻结余额
   - 解冻金额：从冻结余额扣除，增加到可用余额
4. 更新用户余额和冻结余额
5. 记录余额明细（businessType=14）
6. 记录操作日志

## 数据库影响
- 更新 `tb_member` 表中的 `assets` 字段（可用余额）
- 更新 `tb_member` 表中的 `frozenBalance` 字段（冻结余额）
- 在 `tb_user_balance_detail` 表中插入新的交易记录
- 影响用户可用余额、冻结余额和交易历史

## 使用场景
- 后台管理员冻结用户资金
- 风险控制时冻结可疑账户
- 客服处理用户资金纠纷
- 系统维护时的资金冻结
- 解冻用户被冻结的资金

## 错误处理
- 用户ID为空或无效
- 金额小于等于0
- 操作类型无效
- 目标用户不存在
- 冻结时可用余额不足
- 解冻时冻结余额不足
- 数据库操作异常

## 返回结果
- **成功**: 返回成功消息 "冻结金额操作成功"
- **失败**: 返回具体错误信息

## 权限要求
- 当前权限注解: `@RequiresPermissions("member:user:freeBalance")`
- 需要相应的权限配置

## 注意事项
1. 金额单位为分，确保精度
2. 冻结金额前会检查可用余额充足性
3. 解冻金额前会检查冻结余额充足性
4. 所有操作都会记录详细日志
5. 使用事务确保数据一致性
6. 自动记录余额明细，便于后续查询

## 余额明细记录
- **业务类型**: 14（冻结金额操作）
- **渠道**: 后台冻结操作
- **备注**: 使用传入的备注或默认操作类型描述
- **状态**: 1（正常）

## 冻结金额操作说明
### 冻结金额 (balance_type=1)
- 从用户可用余额中扣除指定金额
- 将扣除的金额增加到冻结余额
- 冻结后用户无法使用该部分资金

### 解冻金额 (balance_type=2)
- 从用户冻结余额中扣除指定金额
- 将扣除的金额增加到可用余额
- 解冻后用户可以正常使用该部分资金

## 业务规则
1. 冻结金额不能超过用户可用余额
2. 解冻金额不能超过用户冻结余额
3. 冻结和解冻操作都会影响用户的资金流动性
4. 所有操作都会记录完整的操作轨迹
