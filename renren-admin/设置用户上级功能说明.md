# 设置用户上级功能说明

## 功能概述
`updateUp` 接口用于设置用户的上级关系，通过用户ID和上级用户的手机号来建立上下级关系。

## 接口信息
- **接口路径**: `PUT /user/updateUp`
- **接口名称**: 设置用户上级
- **操作日志**: 设置用户上级

## 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 用户ID |
| mobile | String | 是 | 上级用户手机号 |

## 请求示例
```bash
PUT /user/updateUp?id=1958922146164248577&mobile=13800138000
```

## 功能特性
1. **参数验证**: 验证用户ID和手机号的有效性
2. **用户存在性检查**: 确保目标用户和上级用户都存在
3. **自引用检查**: 防止用户设置自己为上级
4. **事务管理**: 使用事务确保数据一致性
5. **详细日志**: 记录操作过程和结果

## 业务逻辑
1. 验证输入参数（用户ID、上级手机号）
2. 查询目标用户信息
3. 根据手机号查询上级用户信息
4. 检查是否设置自己为上级
5. 更新用户的上级ID和上级姓名
6. 记录操作日志

## 数据库影响
- 更新 `tb_member` 表中的 `up_id` 和 `up_name` 字段
- 影响用户关系结构

## 使用场景
- 建立用户推荐关系
- 设置代理层级结构
- 管理用户团队关系
- 建立分销体系

## 错误处理
- 用户ID为空或无效
- 上级手机号为空
- 目标用户不存在
- 上级用户不存在
- 不能设置自己为上级
- 数据库操作异常

## 返回结果
- **成功**: 返回成功消息 "上级设置成功"
- **失败**: 返回具体错误信息

## 权限要求
- 当前权限注解: `@RequiresPermissions("member:user:updateUp")`
- 需要相应的权限配置

## 注意事项
1. 上级用户必须真实存在
2. 不能形成循环引用
3. 操作会记录详细日志
4. 使用事务确保数据一致性
