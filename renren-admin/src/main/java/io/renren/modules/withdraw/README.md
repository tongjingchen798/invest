# 提现审核模块

## 概述

提现审核模块提供了管理员审核用户提现申请的功能，支持多种审核状态和相应的业务逻辑处理。

## 接口说明

### 提现审核接口

**接口地址**: `/admin/withdraw/withdrawSH`

**请求方式**: `POST`

**请求数据类型**: `application/json`

**响应数据类型**: `*/*`

#### 请求参数

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| -------- | -------- | ----- | -------- | -------- | ------ |
| dto | dto | body | true | 提现审核 | 提现审核 |
| &emsp;&emsp;id | 提现记录id | | false | integer(int64) | |
| &emsp;&emsp;remark | 备注 | | false | string | |
| &emsp;&emsp;state | 审核通过 1 驳回 3 手动转款 2 再次提交 5 | | false | integer(int32) | |
| &emsp;&emsp;sysUpdateUserId | 操作人id | | false | integer(int64) | |
| loginUserId | loginUserId | header | true | integer(int64) | |

#### 审核状态说明

- **1**: 审核通过 - 提现申请被批准
- **2**: 手动转款 - 管理员手动处理转款
- **3**: 审核驳回 - 提现申请被拒绝，资金将退回用户
- **5**: 再次提交 - 用户重新提交提现申请

#### 响应状态

| 状态码 | 说明 | schema |
| -------- | ----- | ----- | 
| 200 | OK | 响应 |
| 201 | Created | |
| 401 | Unauthorized | |
| 403 | Forbidden | |
| 404 | Not Found | |

#### 响应参数

| 参数名称 | 参数说明 | 类型 | schema |
| -------- | ----- | ----- |----- | 
| code | 编码：0表示成功，其他值表示失败 | integer(int32) | integer(int32) |
| data | 响应数据 | object | |
| msg | 消息内容 | string | |

#### 请求示例

```javascript
{
  "id": 123456,
  "remark": "审核通过",
  "state": 1
}
```

#### 响应示例

```javascript
{
  "code": 0,
  "data": {},
  "msg": "审核操作成功"
}
```

## 业务逻辑

### 审核流程

1. **状态验证**: 只有待审核状态(0)的订单才能进行审核
2. **参数验证**: 验证提现记录ID、审核状态等参数
3. **状态更新**: 更新订单状态、审核时间、操作人等信息
4. **业务处理**: 根据审核状态执行相应的业务逻辑

### 状态处理

- **审核通过**: 无需额外处理，资金已在前端提现时扣除
- **手动转款**: 无需额外处理
- **审核驳回**: 需要将资金退回给用户（待实现具体逻辑）
- **再次提交**: 无需额外处理

## 技术实现

### 核心类

- `AdminWithdrawController`: 提现审核控制器
- `AdminWithdrawService`: 提现审核服务接口
- `AdminWithdrawServiceImpl`: 提现审核服务实现
- `WithdrawAuditDTO`: 提现审核数据传输对象

### 数据库操作

- 使用MyBatis-Plus进行数据库操作
- 支持事务管理，确保数据一致性
- 记录操作日志和状态变更

### 安全特性

- 操作人身份验证
- 参数合法性校验
- 状态变更权限控制
- 完整的操作日志记录

## 使用说明

### 1. 发送审核请求

```bash
curl -X POST "http://localhost:8080/admin/withdraw/withdrawSH" \
  -H "Content-Type: application/json" \
  -H "loginUserId: 12345" \
  -d '{
    "id": 123456,
    "remark": "审核通过",
    "state": 1
  }'
```

### 2. 处理审核驳回

当审核状态为驳回(3)时，系统会自动记录需要退回的资金信息，具体退回逻辑需要根据业务需求实现。

### 3. 查看审核结果

审核完成后，可以通过提现订单查询接口查看订单状态变更情况。

## 注意事项

1. **权限控制**: 只有具有相应权限的管理员才能进行提现审核
2. **状态限制**: 只能审核待审核状态的订单
3. **事务安全**: 所有审核操作都在事务中执行，确保数据一致性
4. **日志记录**: 所有操作都会记录详细日志，便于审计和问题排查
