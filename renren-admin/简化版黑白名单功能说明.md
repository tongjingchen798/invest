# 简化版黑白名单功能说明

## 功能概述
为黑白名单功能新建了一张专门的表 `tb_blacklist`，结构简单清晰，只包含必要的字段，提供完整的黑白名单管理功能。

## 数据库设计

### 表结构
```sql
CREATE TABLE `tb_blacklist` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `mobile` varchar(20) NOT NULL COMMENT '会员账号',
  `type` tinyint(4) NOT NULL DEFAULT '1' COMMENT '类型：1-白名单，2-黑名单',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_id` (`user_id`),
  KEY `idx_mobile` (`mobile`),
  KEY `idx_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='黑白名单表';
```

### 字段说明
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | bigint | 主键ID，自增 |
| user_id | bigint | 用户ID，唯一约束 |
| mobile | varchar(20) | 会员账号 |
| type | tinyint | 类型：1-白名单，2-黑名单 |

## 功能特性

### 1. 查询黑白名单
- **接口**: `GET /user/getAllBlackList`
- **功能**: 分页查询黑白名单，支持按会员账号和类型筛选
- **参数**: 
  - `page`: 页码
  - `limit`: 每页记录数
  - `mobile`: 会员账号（可选）
  - `type`: 类型筛选（可选）

### 2. 新增黑白名单
- **接口**: `POST /user/addblack`
- **功能**: 将用户添加到白名单或黑名单
- **请求方式**: `POST`
- **请求类型**: `application/json`
- **参数**:
  - `userId`: 用户ID
  - `mobile`: 会员账号
  - `type`: 类型（1-白名单，2-黑名单）
- **请求示例**:
  ```json
  {
    "userId": 123,
    "mobile": "13800138000",
    "type": 1
  }
  ```

### 3. 删除黑白名单
- **接口**: `DELETE /user/deleteblack`
- **功能**: 删除指定的黑白名单记录
- **请求方式**: `DELETE`
- **请求类型**: `application/x-www-form-urlencoded`
- **参数**:
  - `id`: 黑白名单记录ID (query参数)
  - `loginUserId`: 登录用户ID (header参数)
- **响应示例**:
  ```json
  {
    "code": 0,
    "data": {},
    "msg": "用户从白名单中移除成功"
  }
  ```

### 4. 从黑白名单中移除用户
- **接口**: `DELETE /user/removeFromBlacklist`
- **功能**: 从黑白名单中移除指定用户
- **参数**:
  - `id`: 黑白名单记录ID

### 4. 检查用户状态
- **功能**: 检查用户是否在白名单或黑名单中
- **用途**: 可用于业务逻辑中的权限控制

## 优势

### 1. 结构简单
- 只保留必要字段，避免冗余
- 表结构清晰，易于维护

### 2. 性能优化
- 专门的索引设计，查询性能好
- 唯一约束确保数据一致性

### 3. 功能完整
- 支持完整的CRUD操作
- 提供业务检查方法

### 4. 扩展性好
- 可根据需要添加新字段
- 支持复杂的业务逻辑扩展

## 使用场景

### 1. 用户权限控制
- 白名单用户：享受特殊权限或服务
- 黑名单用户：限制某些操作或服务

### 2. 风控管理
- 识别风险用户
- 管理VIP客户

### 3. 业务规则
- 根据黑白名单状态执行不同业务逻辑
- 提供差异化的用户体验

## 注意事项

1. **唯一性约束**: 每个用户只能在黑白名单中出现一次
2. **类型限制**: 类型字段只能是1（白名单）或2（黑名单）
3. **数据一致性**: 删除操作会物理删除记录，确保数据干净
4. **权限控制**: 需要管理员权限才能操作黑白名单
