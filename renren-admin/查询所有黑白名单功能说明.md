# 查询所有黑白名单功能说明

## 功能概述
`getAllBlackList` 接口用于后台管理员查询系统中的黑白名单用户，支持分页查询、条件筛选和排序功能。

## 接口信息
- **接口路径**: `GET /user/getAllBlackList`
- **接口名称**: 查询所有黑白名单
- **请求方式**: GET
- **请求数据类型**: application/x-www-form-urlencoded

## 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| page | Integer | 是 | 当前页码，从1开始 |
| limit | Integer | 是 | 每页显示记录数 |
| agent | Long | 否 | 代理下拉框 |
| mobile | String | 否 | 用户账号 |
| order | String | 否 | 排序方式，可选值(asc、desc) |
| salesmanid | Long | 否 | 业务员下拉框 |
| type | String | 否 | 类型：1-白名单，2-黑名单，不传查所有 |

## 请求示例
```bash
GET /user/getAllBlackList?page=1&limit=10&type=1
```

## 功能特性
1. **分页查询**: 支持分页查询，可设置页码和每页记录数
2. **条件筛选**: 支持按代理、手机号、业务员、类型等条件筛选
3. **类型区分**: 支持查询白名单(type=1)、黑名单(type=2)或所有黑白名单
4. **排序功能**: 支持按创建时间升序或降序排序
5. **数据转换**: 自动将数据库实体转换为DTO格式返回

## 业务逻辑
1. 验证分页参数的有效性
2. 构建查询条件（代理、手机号、业务员、类型筛选）
3. 执行分页查询
4. 将查询结果转换为DTO格式
5. 返回分页数据

## 数据库影响
- 查询 `tb_member` 表中的黑白名单用户
- 根据 `blacklist_type` 字段区分白名单(1)和黑名单(2)
- 不影响数据库数据，仅进行查询操作

## 使用场景
1. **黑白名单管理**: 管理员查看系统中的黑白名单用户
2. **用户筛选**: 按不同条件筛选黑白名单用户
3. **数据统计**: 统计黑白名单用户数量和分布
4. **权限控制**: 根据黑白名单状态控制用户访问权限

## 返回数据格式
```json
{
    "code": 0,
    "data": {
        "list": [
            {
                "id": 123,
                "mobile": "13800138000",
                "type": 1,
                "userId": 123
            }
        ],
        "sum": {},
        "total": 1
    },
    "msg": ""
}
```

## 注意事项
1. 页码必须大于0，每页记录数必须在1-1000之间
2. 类型参数为可选，不传时查询所有黑白名单
3. 排序方式默认为按创建时间倒序
4. 返回的userId与id字段值相同
5. 需要管理员权限才能访问此接口

## 错误处理
- 参数验证失败时返回相应的错误信息
- 数据库查询异常时抛出RuntimeException
- 所有异常都会被捕获并返回友好的错误信息

## 相关接口
- 此接口为查询接口，不涉及数据修改
- 可与黑白名单管理相关接口配合使用
- 支持与其他用户管理接口集成
