# 手工调整余额功能说明

## 功能概述
`addBalance` 接口用于后台管理员手工调整用户余额，支持增加和减少余额操作，并记录详细的交易明细。

## 接口信息
- **接口路径**: `PUT /user/addBalance`
- **接口名称**: 手工调整余额
- **操作日志**: 手工调整余额

## 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 用户ID |
| balance | Long | 是 | 金额（分） |
| balance_type | Integer | 是 | 操作类型：1-增加余额，2-减少余额 |
| remark | String | 否 | 备注信息 |

## 请求示例
```bash
PUT /user/addBalance?id=1958922146164248577&balance=10000&balance_type=1&remark=测试增加余额
```

## 功能特性
1. **参数验证**: 验证用户ID、金额和操作类型的有效性
2. **余额检查**: 减少余额时检查用户余额是否充足
3. **事务管理**: 使用事务确保数据一致性
4. **详细日志**: 记录操作过程和结果
5. **余额明细**: 自动记录余额变动明细

## 业务逻辑
1. 验证输入参数（用户ID、金额、操作类型、备注）
2. 查询目标用户信息
3. 根据操作类型调整余额：
   - 增加余额：直接累加
   - 减少余额：检查余额充足性后扣除
4. 更新用户余额
5. 记录余额明细（businessType=13）
6. 记录操作日志

## 数据库影响
- 更新 `tb_member` 表中的 `assets` 字段
- 在 `tb_user_balance_detail` 表中插入新的交易记录
- 影响用户余额和交易历史

## 使用场景
- 后台管理员手工调整用户余额
- 系统维护时的余额修正
- 客服处理用户余额问题
- 财务对账和调整

## 错误处理
- 用户ID为空或无效
- 金额小于等于0
- 操作类型无效
- 目标用户不存在
- 减少余额时余额不足
- 数据库操作异常

## 返回结果
- **成功**: 返回成功消息 "余额调整成功"
- **失败**: 返回具体错误信息

## 权限要求
- 当前权限注解: `@RequiresPermissions("member:user:addBalance")`
- 需要相应的权限配置

## 注意事项
1. 金额单位为分，确保精度
2. 减少余额前会检查余额充足性
3. 所有操作都会记录详细日志
4. 使用事务确保数据一致性
5. 自动记录余额明细，便于后续查询

## 余额明细记录
- **业务类型**: 13（手工调整余额）
- **渠道**: 后台手工调整
- **备注**: 使用传入的备注或默认操作类型描述
- **状态**: 1（正常）
